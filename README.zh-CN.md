# GoblinScript

丢进一个视频，得到一个 funscript。**由真正的哥布林制作。**

一只哥布林看着视频，随手涂出一份对得上的脚本：动作在哪里就有笔划，按屏幕上的运动对齐时间。结果落在视频旁边，名为 `video.funscript`，任何读 funscript 的播放器都能直接用。把它当成一份扎实的初稿——哥布林的目标是踩准节奏和时间，其余的东西你可以在自己喜欢的编辑器里慢慢微调。

> **这是 ofs69 的 GoblinScript 的一个分支。**
> [Kotone-Hikaru/GoblinScript-Sakuya](https://github.com/Kotone-Hikaru/GoblinScript-Sakuya)
> 建立在 [ofs69/GoblinScript](https://github.com/ofs69/GoblinScript) 之上——GPU
> 节流、跨段工作台、手绘波形片段、滑杆面板、给画面用的遮蔽层、批量裁剪轮次，以及一个
> 在它需要你时会来到前面的窗口。应用本身、它的页面、训练流水线和模型都是
> **ofs69 的工作**；凡是没有列在

## 使用方法

双击 `goblinscript.exe`，终端里会打开一个选择器：用方向键浏览，空格键选中，按 **S** 让哥布林开工。或者从命令行：

```
goblinscript video.mp4                  the script appears next to the video
goblinscript D:\clips                   every video in that folder
goblinscript video.mp4 --out D:\scripts put the scripts somewhere else
goblinscript video.mp4 --model v0.4.0  draft with another of the models it carries
goblinscript video.mp4 --models v0.5.1,v0.3.0
                                        both, from one look at the video:
                                        video.funscript and video.v0.3.0.funscript
goblinscript video.mp4 --throttle gentle
                                        keep the GPU usable; see the fork's notes below
goblinscript D:\clips --batch-crop      judge every crop at the end, then draft them all
```

一次发布带好几个模型，每个都以最早发布它的那个版本命名，而且它们看视频的方式完全一样——所以多跑一个模型只花几秒，而不是再编码一遍。`--model` 挑一个，`--models` 把它们并排写出来、不走复核。复核页在出稿时用每个模型读同一段视频，所以它能立刻切换一份脚本所用的模型。视频下方，**script** 标出正在写这份脚本的模型，**vs** 在它下面再铺一条线：另一个模型的、用同样这些旋钮写出的线，或者是那份 **pinned** 脚本，按它当时带着的模型和旋钮原样保留。**⇄**（或 **x**）交换脚本和它下面那条线，于是选择就是在视频播放时来回翻看完成的。每份脚本都记下写它的模型和设置。

在哥布林开工之前，浏览器里会打开一个页面，在每一个镜头上画出它们即将看的那块画面。如果它们挑错了区域，就把那个矩形拖到动作上；如果挑对了，就直接点过去；你画的结果会为这个视频保留下来。用 `--no-crop-edit` 或在选择器里按 **K** 关掉这个页面，整批任务就可以没人守着键盘跑完。

跑一批的时候，在每个视频转码时顺便判定裁剪，意味着每个视频都要你坐下来一次。**`--batch-crop`**（或选择器里的 **J**）让整轮改成走两遍：第一遍为每个视频转码、切分并询问裁剪，第二遍用缓存里的答案把它们全部出稿，而且完全不开页面。裁剪依然是在昂贵阶段*之前*决定的，所以改正它依然不花代价——变的只是*什么时候*问你。它默认关闭，因为它用机器时间来省你的时间：见[批量裁剪轮次](#批量裁剪轮次)。

`goblinscript --help` 列出所有选项。VR 视频会在浏览器里打开一个页面让你瞄一次；普通的平面视频完全不需要任何参数。自带英文和中文，你翻译的任何 `languages/*.json` 都会出现在 **G** 键上。已有的脚本不加 `--force` 绝不会被覆盖，视频文件本身则始终不动。

**你干活的时候，屏幕上没有任何东西必须能被看清。** 两个浏览器页面都带一个遮蔽层——两块盖在画面上的遮挡，用页面上的按钮或者循环按 **H** 都能切到。见[遮蔽层](#遮蔽层)。

### 作为编辑器后端运行

`goblinscript --serve` 把哥布林作为另一个程序的 sidecar 来跑：一个 funscript 编辑器，在自己的时间轴下面画出草稿，并且每次作者挪动一个点就重新调样式。它绑定到 localhost，打印一行带 `port` 和访问 `token` 的 JSON，然后一直应答请求，直到它的标准输入关闭，或者有客户端 POST `/quit`。那条命令行上的每个出稿选项（`--cache`、`--no-autocrop`、`--dwells` ...）就是每个会话出稿时所用的设置。

**这个 API 不稳定。** 只要有更好的形状，路由、字段和单位就会改，不给别名，也不升版本号；和某个构建一起发布的那份客户端才是配它的那个。每个请求都在 `x-goblin-token` 头里带 token。`API.md` 是参考：每条路由、每个字段、那些页面，以及一个二十行的客户端。

| 路由 | 做什么 |
|---|---|
| `GET /health` | 构建、模型、会话数量 |
| `GET /manifest` | 部署常量、默认参数、预设阶梯 |
| `POST /sessions` `{video, vr?, crop_edit?, browser?}` | 为一个视频打开（或加入）会话并出稿 |
| `GET /sessions/ID` | 正在进行的阶段、等待中的页面、已完成的阶段，或者就绪后该片段的时钟 |
| `GET /sessions/ID/tracks?from_ms&to_ms` | 视频时钟上逐行的轨道 |
| `POST /sessions/ID/style` `{params..., pins?, from_ms?, to_ms?}` | 调好样式的动作，单位毫秒 |
| `POST /sessions/ID/workbench` `{browser?}` | 这个会话的复核页，以 `{url}` 形式返回 |
| `DELETE /sessions/ID` | 忘掉这个会话（它的缓存保留） |
| `POST /quit` | 退出 |

需要人来做的决定，仍然交给控制台为他们打开的浏览器页面。编码之前是 VR 瞄准页和裁剪页：走到其中一个的会话状态读作 `working`，页面的 `key` 和 `url` 在 `page` 下，在那里按下 Done 之后出稿继续。`vr` 省略时由探测器判断，`true` 表示不管探测器怎么想都打开瞄准页（并且给一个已经有瞄准的视频重新瞄一次），`false` 表示直接对原始帧出稿，或者给一个 sidecar 对象表示原样应用。`crop_edit` 省略表示刚探测完裁剪时打开裁剪页，`true` 表示总是打开，`false` 表示从不。`browser: false` 把打开页面的活留给客户端，否则由服务端打开。

出稿之后是**工作台**：复核页，带着视频、模拟器和每个样式旋钮，开着的时候一直占着自己的端口。想开几次就开几次。在那里定下来的旋钮从那时起就是这个会话的样式——每次样式调用都从它们出发，状态把它们放在 `params` 和 `flags` 下带回来，`style_rev` 统计改动的次数，好让客户端知道该再问一次。

一次样式调用接受复核页 POST 的那些字段，每一个都是可选的、缺省时回落到会话的样式，另外还有 `pins`：`[[ms, pos], ...]`，作者放置的顶点。一个 pin 会替换模型在它 60 ms 以内的顶点，并把它周围的电平朝作者的那一个弯过去；模型的其他折返时间留在原处。种子挪动了就是 head 阶段的工作：这个调用回 `409 redecoding`，会话状态读作 `working`，直到轨道回来。

## 这个分支添加了什么

下面所有内容都是 [Kotone-Hikaru](https://github.com/Kotone-Hikaru) 在上游 `5bf8d6f` 之上做的工作，是为了复核页和它运行的那块 GPU 写的。这些东西不涉及的地方，应用和它的流水线都没有改动。模型包里多带两个模型，是在这里训练的，而不是上游发布的——见[两个 anime 模型](#两个-anime-模型)，那里也说明了为什么你该继续用默认的那个，除非你的素材看起来像它们的训练集。

其中三个是关于出稿的——一份脚本怎么被切成片段、一个片段怎么能画出来而不是靠模型生成、以及干活时怎么让 GPU 保持可用。后三个是关于这项工作的另一半，那些花在*观看和决定*上的小时：盖住一幅不该被身后的人读到的画面、一次坐着把一批的裁剪都判完，以及一个在需要你的时候会来到前面的窗口。它们是这里最便宜的东西，而第一个值得你在上班时间打开一个视频之前先知道。

### 跨段工作台

复核页在时间轴下面长出了第二层：**spans**。一把剃刀把草稿切成片段，每个片段指定写它的模型，于是一个模型读不好的场景可以交给另一个模型，而不用把其余部分重新出稿。片段就是你拖动的边，拖动一条边可以吸附到最近的镜头切换（**S**）。视频自己的切换也是可编辑的（**B**）——增加或删掉一个都会重跑 head 阶段，因为它改变了模型被喂进去的东西。工作台里的任何东西都不碰草稿文件：它是会话的编辑，和一个旋钮一样。

每个片段还带**自己的强度**，0 到 5，其中 1 是模型自己的答案。它围绕片段*自己的均值*缩放，而不是围绕中间值，所以把一个安静的波形调大是把它撑宽，而不是把它压向地板——而且它移动的是片段的顶点，而不是它们被找到的那些行，所以更高的设置绝不会让片段丢掉一个点。

**置信度建议**可以按每个模型自己的置信度，为每个片段提议一个模型，取样方式是各做一次即时重调样式。它只是个提议，仅此而已：不问它就不开，应用它也有自己的按钮。哪些模型能上选票由你按模型逐个设定，这个选择记在 `settings.json` 里；被你关掉的模型永远不会被取样，所以它不能花掉你的等待，也不能靠一个你不信的自评赢下一个镜头。

每一步都可以撤销（**Ctrl+Z** / **Ctrl+Shift+Z**），一次编辑一步，tooltip 里会写明它改动的那一个片段、切换点、模型或合并。

### 手绘波形片段

一个片段可以按你画的波形来写，而不是由模型生成。自带六种波——triangle、sine、rounded triangle、single peak、pulse 和 one-way glide——每种都有自己的旋钮（顶点位置、圆角半径、上升与下降的占比、charge、深度...）。面板上的每个数字同时也是一个你能拖的滑杆，而两个边界是一条双头带，你还可以从中间抓住它整体平移，跟单手柄滑杆一样。

这些波存在 `src/waves.json` 里，是**数据**，不是代码：一个分段的时长和电平是关于该波自身参数的算术表达式，所以增加一个旋钮或者改变一个旋钮的形状，都是改那个文件，而不是改代码。这个文件被烤进二进制，但放在 **exe 旁边**的 `waves.json` 会优先于它被读取——所以改那份副本再刷新页面就能重新调形状，不用重新构建，也不用重装。画出来的片段是从它的波*解*出来的，而不是在帧网格上扫出来的，所以一个 triangle 正好到达 0 和 100，而不会差一行停下。每个片段有两个开关，让它忽略速度上限（**ignore limits**）和视频的镜头切换（**ignore cuts**）——后一个默认打开，因为素材里的一个切换不是你画里的一个切换。

### GPU 节流

`--throttle` 让哥布林在出稿时不全占住整块 GPU，于是一台机器在长时间跑批时还能用：一个闭环采样 GPU 负载，在编码窗口之间小睡一会儿，睡多久按它刚做完的工作量所占的占空比来定。它带了护栏，所以不会来回震荡——一个死区、一个平均后的负载、每步的上升和下降限制，以及在环可以反向之前的一个停留时间——而且它是故障放行的，读不到 GPU 时自己解除武装，而不是卡住一次出稿。三个预设——`gentle`、`balanced`、`aggressive`——在选择器里用 **P** 循环切换，并记在 `settings.json` 里；`--throttle custom` 配合各个 `--throttle-*` 参数手动调，`--no-throttle` 则覆盖记住的选择。启动画面总会报告它处在哪个状态，所以「是不是有什么东西在压着我的 GPU」一眼就能回答。`goblinscript --help` 列出这些预设和每个 `--throttle-*` 参数；预设本身就是选择器循环的那三个。

### 遮蔽层

两个显示画面的页面——裁剪页和复核页——都能把它盖住。不是暂停它，也不是停下工作：**盖住它**，因为脚本是靠看视频写出来的，而这份材料不该留在一个路过的同事能读到的屏幕上。

两块遮挡，各自是一个开关（按亮着的那一个就把画面放回来），所以两个按钮承载三个状态，而且状态是看得见的：

* **still**——一张带静态纹理的不透明卡片。它不花任何代价：合成器就像混任何背景一样混它。
* **frost**——那一帧，按画面的每个方向**八分之一**采样进一个 canvas，*在那个尺寸上*模糊，再由 CSS 放大。

**H** 循环 关 → still → frost → 关。它是一个键而不是一个选择，因为它是被人突然走进来时才去按的，那不是慢慢在两块遮挡之间挑的时候。（选择器把 **H** 用在另一个开关上——下面那个把窗口抬起来的开关——因为终端和一个页面从不会同时拿着键盘。）

两块遮挡都不接收指针事件，所以原生的播放控制条、裁剪矩形和它的手柄、模拟器以及每一处读数在它们后面照常工作——一个矩形是按它待在哪儿来判定的，这不需要读像素。而且 frost 会在*暂停时*跟随一次跳转，这正是两个页面实际被使用的方式：一个只在播放时刷新的遮挡会把上一帧留在屏幕上，而那恰恰是它存在要防住的泄漏。

frost 用 canvas 而不是对视频用 `filter: blur()`，只有一个原因，而这就是便宜和免费的区别。在一个小 canvas 里施加的模糊，到达合成器时已经是一张完成的位图。显而易见的那个做法——在一个 `transform: scale(8)` 包裹层里对视频用 CSS 模糊——不是这样：合成器按滤镜层最终被绘制的尺寸来栅格化它，于是模糊在放大后的尺度上重跑一遍，省下来的就蒸发了。两者差大约 **64×**（面积）。模糊半径本身在两种做法里都近乎免费：Skia 的模糊是三趟 box，而 box 模糊用滑动窗口求和，所以代价与半径无关。

### 批量裁剪轮次

`--batch-crop`（选择器里的 **J**）把每一个裁剪都放到**一批的末尾**去问，而不是每个视频问一次，做法是让整轮走两遍：

| | 它做什么 |
|---|---|
| **pass 1** | 转码 → 曝光 → 切换点 → 探测裁剪 → **打开页面**。停在这里。 |
| **pass 2** | 裁剪都已决定。从缓存里取每个答案，跑昂贵的那一步。**不开任何页面。** |

让这件事成为一次调度改动而不是一次重新架构的那个性质，流水线本来就有：**裁剪在昂贵的那一步之前就决定了**，而这才让改正它不花代价。批处理只改变*什么时候*问你，从不改变这个问题*落在哪里*（相对于它所影响的那一步）。

它的代价，以及它为什么默认关闭：视频 *N+1* 的转码过去跑在视频 *N* 昂贵阶段留下的 GPU 空当里。把两遍拆开就去掉了这个重叠，于是一批要花**更多纯机器时间和更少你的时间**。这是一个该主动去选的交换，不是一个该事后发现的交换。

单个视频从不会被拆成两遍——没有什么可批的，而第二遍会为了到达同一个地方而多走一遍整个缓存。第一遍的工作文件是刻意**不**清理的：归一化结果、切换点列表和裁剪计划，正是第二遍回来要的东西。

### 会自己来到前面的窗口

当一个阶段停下来等人——裁剪页、复核页——浏览器窗口如果漂到别的东西后面，就会被提到 Z 序的最前面。一次跑批卡在一个没人看得见的页面上，看起来和一次还在干活的跑批一模一样，这就是它要防的那种失败。

它**不**拿键盘焦点，而这是整个设计，不是设计的一半。在 Windows 上，取得前台是有特权的：除非调用者已经是前台进程、是由前台进程启动的，或者刚收到过输入，否则会被拒绝。这个程序是一个控制台应用，它的控制台窗口属于终端，而等到某个阶段需要人注意的时候，人早就挪去别处了——所以它基本上从不满足条件，而抢焦点也只会静默退化成任务栏闪烁。重排 Z 轴*不*是有特权的：把置顶位开了又关，两半都带 `SWP_NOACTIVATE`，就把窗口提到邻居之上，而不向系统要任何东西。

代价很小，而且说得明白：窗口起来，光标不来，于是你点它一下继续干活。另一个选择——真正去抢焦点——可能吞掉别人正往另一个窗口里打的字，而一个把自己冒出来的工具没道理干这种事。

窗口是按标题找到的，用页面自己的 `<title>` 做不区分大小写的匹配。但只有标题还不够，而发现这一点花掉了一个 bug：这条流水线跑的那个控制台也用程序的名字作标题，所以一个裸的子串搜索同样容易匹配到那个黑色终端框，就像匹配浏览器一样，而最后哪个赢了，取决于你上一次碰的是哪个——纯属偶然。因此选择是按窗口的 **class** 做的：浏览器 class 胜出（`Chrome_WidgetWin_*` 覆盖 Chrome、Edge、Brave、Vivaldi 和 Opera；还有 `MozillaWindowClass`、`IEFrame`），终端 class 无论它的标题写着什么**永远**不会被抬起来，而其他任何匹配标题的 class 仍然被接受，这样一个不熟悉的浏览器能用，而不是静默地什么也不做。

这个开关和其他常设偏好一起住在选择器里（**H**），并记在 `settings.json` 里。它默认**开**：不像那些要花掉一次等待或者重写片段的开关，它只决定一个窗口是否可见。

### 两个 anime 模型

模型包带了两个上游不发布的模型。两个都是在这里用 ofs69 自己的训练流水线、在 anime 和 MMD 素材上训出来的：一个 **1,029 clips（77.6 hours）** 的语料，其中 **128 clips（9.7 hours）被留出训练之外**，下面每一个数字都只来自这些被留出的片段。`anime-v1` 在剩下的 901 个上训练，`anime-v1.1-from-0.3.0` 在两次跑之间丢掉两个片段之后的 899 个上训练。两个都从上游的一个 checkpoint 出发。它们就是 `anime-v1` 和 `anime-v1.1-from-0.3.0`，而**默认仍然是上游的 `v0.5.1`**。没有任何东西替你选中它们。

它们不是一种普遍的改进，在不像它们训练集的素材上，很可能比默认的更差。因为留出集就取自同一个 anime 语料，这些数字衡量的是「这个模型是否贴合 anime 素材」——而不是「这个模型是否更好」：

| 对照参照臂 | corr | travel | 慢速段尖峰 `sl>3x` |
|---|---|---|---|
| upstream `v0.6.0` (reference) | 0.359 | 0.690 | 5.30 |
| `anime-v1` | 0.541 | 0.523 | **1.73** |
| `anime-v1.1-from-0.3.0` | **0.564** | 0.639 | 2.65 |

`corr` 是与人类脚本的一致程度；`travel` 是脚本实际用到了笔划量程的多大一部分；`sl>3x` 统计慢速段落里快了三倍的尖峰——一种伪影，越低越好。

注意基线是什么：`v0.6.0`，也就是训练期间用来和这两个比较的那个 checkpoint。**默认的 `v0.5.1` 从未在这个留出集上跑过**，所以这张表说的不是这两个和开箱即得的东西相比如何——只是它们和那一个上游臂相比如何。

从这张表里能带走三件事。第一，**`anime-v1` 是安静的那个**：它用振幅换平静——travel 降到 0.523，尖峰降到上游的三分之一。第二，**`anime-v1.1` 在平均值上赢了**（最好的 `corr`，travel 接近上游）**但这是用比 `anime-v1` 更多的尖峰换来的**——2.65 对 1.73，仍然好过上游的 5.30，但已不再是那个安静的模型。它带着 `amp_cap_x=2.0` 发布，这是一个训练之后扫出来的推理期振幅上限：在未调校的默认值下同一个 checkpoint 读数是 3.33，关掉上限则读 4.19。第三，**这些数字没有一个是在 anime 之外的东西上测的**，所以它们对实拍、3D 渲染或者你拿这个应用去指的任何别的东西都没说什么。它们是试一试这些模型在 anime 上的理由，不是相信它们普遍更好的理由。

这就是为什么上游的 `v0.5.1` 仍然是默认，也是为什么 `anime-v1.1` 不被称作一个完成的模型：在它自己的留出集上，它把每个平均值都改善了，同时把伪影地板弄得更差，而按这个项目自己的评估规则，一个用更差的伪影地板换来的平均值是更差的模型。它在这里是因为训练做完了、证据是真的，不是因为它被推荐。

如果你的素材是 anime 或 MMD，就用 `--model anime-v1`（或者在复核页里挑它）。如果不是，就别动默认。

### 较小的改动

* **#strip** 有两种操作模式：*play*，它跟随视频，点一下就跳过去；以及 *edit*，滚轮平移，Ctrl+滚轮缩放，拖动一个边界移动一个切换点，右键挑选模型（**E** 切换；**Tab** 在任何地方做同样的事）。
* 两侧的栏都是**可调整宽度**的：拖片段列表或者工作台的边缘。两者共用一个宽度——它们坐在同一个舞台的两侧，所以把列表加宽好读清里面的模型，旋钮也会跟着加宽——而这个宽度记在 `settings.json` 里，所以它能挺过一次刷新、一次清缓存和换一个浏览器。
* **裁剪页**可以增加、移动和删除它各个镜头的起点——一个长镜头里主体走出了矩形，就是探测器判不了而人能判的那种情况（在播放头处按 Enter、按 Delete，或者在条上拖）。每次编辑都被夹到帧网格上，并且严格落在它两个邻居之间，所以页面做不出一个分段解码器会拒绝的计划。边界 0（片段自己的起点）可以被增加，但从不被移动或删除。
* 条下面的**速度读数**显示播放头处的速率和刚过去那一秒里走过的距离，用和热度条相同的绿到琥珀色标尺来画，两者中任何一个越过上限之后就变成纯红。上限真正在*削*的地方，在条上是泛红的，而条本身就是按速度给自己上色的那条——在整段片段的时间轴上，一条红带会被读成视频的一个属性，而那不是它的意思。
* 视频播放时各个 canvas 以 60 Hz 重绘，不播放时**完全不**重绘：一个暂停的页面不花任何代价，而一个手势立刻绘制，不用等下一个 tick。
* 默认播放音量是 15%，刻意的，且不被记住——这是一个视觉编辑器，安静的默认比吵闹的默认更友好。
* 选择器的选项行带着每一个常设偏好，所以一个被双击起来的 exe——它的用户没有命令行——也能摸到全部：**P** 节流、**O** 打开时的 conf-suggest、**W** GPU 浏览器、**H** 抬起窗口（**J** 批量裁剪）。每一个都记在 `settings.json` 里，并应用到下一批。
* 关掉一个页面就是**取消**，它会停下整批，而不是留下一个进程等一个已经不存在的窗口：页面在被拆掉时会说再见，而一次安静得太久的跑批也会被当成走了。一句再见不会被立刻执行，因为刷新说再见的说法和关闭一模一样——它被短暂按住，然后由页面回来而撤回，所以 **F5 杀不掉一批**。工作文件会保留，所以重跑一个视频就是接着来。
* **版本号有四段**，第四段是**提交计数**，不是构建 id：最后一个数字是这个分支从它自己的基线 tag 以来做了多少次提交。同一个提交重新构建十次，说的是同一件事十遍——这正是重点，因为一个代码没动而它自己在动的数字什么也告诉不了你。每个界面都读那同一个字符串（`--version`、启动横幅、选择器的字标、错误日志、`--serve` 的握手），所以它们不可能互相矛盾。一个没有仓库的构建——一个源码 tarball，没有基线 tag——会回落到 `.0` 并给一条构建警告，而不是失败。
* 每一个新字符串都同时以英文和中文发布（在这个分支的基底之上新增 147 个键，按 `languages/en-US.json` 数）。

## 你需要什么

* **Windows 10（64 位）或 11**，或者 x86-64 上带 glibc 2.38 或更新的 **Linux**（Ubuntu 24.04、Fedora 39、Debian 13、Arch 之类）。
* 一块有 **8 GB 显存**的显卡：Windows 上任何 **DirectX 12** 显卡（NVIDIA、AMD、Intel），或者 Linux 上带显示驱动的 **NVIDIA** 显卡，版本 525 或更新。没有纯 CPU 模式：哥布林思考所用的形态只有 GPU 装得下。
* 对应你显卡的那个包。`windows-dml` 在任何 DirectX 12 显卡上都能跑，是那个小一点的下载。`windows-cuda` 和 `linux-cuda` 要 NVIDIA 显卡，它们自带 NVIDIA 的 CUDA 12 和 cuDNN 9 库，所以 CUDA 不是你另外要装的东西。
* **8 GB 系统内存**，或者更多。
* PATH 上有 [ffmpeg](https://ffmpeg.org/)——Windows 上 `winget install --id Gyan.FFmpeg` 然后开一个新的终端，Linux 上 `sudo apt install ffmpeg`。
* 把 zip 里的每个文件都和 goblinscript 二进制放在同一个文件夹里。库是在那里找到的，别处不行。

在快的 GPU 上大约是视频时长的一半。一切都在你的机器上跑：不上传，不需要联网。

funscript 驱动成人玩具，而哥布林是拿成人视频教出来的。这里没有任何东西是给 18 岁以下的人用的。

## 构建

```
cargo build --release     # builds; no goblins in it yet
cargo test                # green on a bare checkout; see the runtime note below
```

模型不在这个仓库里，但一个**已发布**的 `goblinscript.exe` 会把它自己的交出来。向它要一份，然后让你的构建指向它写出来的东西：

```
goblinscript --dump-bundle bundle          # from a release exe, into ./bundle
cargo run --release -- --bundle bundle VIDEO
```

那就是发布版出稿所用的同一批字节，所以你的构建现在出稿表现一致。如果想改为把它们烤进去——你自己的独立 exe，或者一个完整的发布 zip，旁边放 `LICENSE` 和第三方声明：

```
cargo build --release --features embed     # reads ./bundle at compile time
cargo xtask dist                           # -> dist/goblinscript-VER-windows-dml.zip on Windows,
                                           #    dist/goblinscript-VER-linux-cuda.zip on Linux
```

Windows 构建通过 cargo 取它自己的 ONNX Runtime，不需要设置任何东西。Linux 构建链接微软的 `onnxruntime-linux-x64-gpu_cuda12` 包，也就是那个覆盖所有 NVIDIA 显卡的包：解开它，把 `ORT_LIB_LOCATION` 指向它的 `lib` 文件夹，并设置 `ORT_PREFER_DYNAMIC_LINK=1`。它还需要发行版提供的 `libasound2-dev` 和 `pkg-config`。crate 树在两边都交给 cargo 去取。

一个 CUDA zip 把 NVIDIA 的 CUDA 12 和 cuDNN 9 库放在二进制旁边，打包程序从 `cuda-libs/`（或 `CUDA_LIBS_DIR`）读它们，而从不替你去下载。每个 Linux zip 都是这样，`cargo xtask dist --cuda` 加出来的那个 Windows zip 也是。`cargo xtask cuda-libs` 会打印出该放进那里的确切名字，来源是 NVIDIA 在 <https://developer.download.nvidia.com/compute/> 的可再分发归档。

在检出里 `music/` 是空的，应用静音运行；往里丢的任何 General MIDI `.mid` 文件就成了播放列表。

发布 zip 由 GitHub Actions 从一个版本 tag 构建。检出里缺少的那些输入放在这个仓库常驻的 `bundle` release 上：`bundle.zip`，即两个平台都运行的感知和每个模型，以及 `music.zip`。`bundle.sha256` 钉住某个版本所嵌入的那个 bundle，工作流会拒绝任何别的。

`DEVELOPMENT.md` 是地图：每个阶段做什么、为什么是那个形状，以及为了让它保持诚实而测量了什么。
